# DueBoard v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Historical note:** this is the plan the first implementation followed. The product changed afterwards (dashboard opened from the toolbar instead of the new tab, English-only UI, platform discovery from Brightspace, Pearson and WileyPLUS support) — see the change log in the design document. At the time the UI was bilingual; Chinese UI strings in the original are given here in English.

**Goal:** Build the first DueBoard Chrome extension: automatically read courses, assignments, due dates and resource links from Purdue's Brightspace and from Gradescope, and show them on the new tab in three views — course cards, calendar and to-do.

**Architecture:** A WXT (Manifest V3) extension. All syncing runs in the background service worker: connectors read each platform with the browser's existing sign-in, Gradescope HTML is parsed in an offscreen document, and each platform's last successful result is stored as a snapshot in `chrome.storage.local`. On every read, the pure function `buildDashboard()` merges snapshots, manual entries and user state into what the UI shows.

**Tech Stack:** TypeScript 5.9, WXT 0.21, React 19, Tailwind CSS 4 (`@tailwindcss/vite`), date-fns 4, Vitest + happy-dom + @testing-library/react, `@wxt-dev/auto-icons`.

**Spec:** `docs/superpowers/specs/2026-11-04-dueboard-design.md` (read it fully before starting; the UI follows the mockup board "Final: A + next-deadline banner" at https://claude.ai/artifact/XWfaHHvt7Ps131t3qctoyZ)

## Global Constraints

- Node 22; npm; pin `typescript@~5.9.3` (not 7.x).
- Only `https://purdue.brightspace.com` and `https://www.gradescope.com`.
- Manifest permissions are exactly `storage`, `alarms`, `offscreen`; host_permissions are the two hosts above with `/*`; the new tab uses `chrome_url_overrides.newtab`. No `tabs`, `cookies` or `<all_urls>`.
- GET requests only, always with `credentials: 'include'`; at most 4 concurrent Brightspace requests.
- Background sync every 30 minutes (alarm `dueboard-sync`); opening the dashboard syncs when the last sync is older than 5 minutes.
- Due state: ≤48 hours `urgent`, ≤7 days `soon`, later `normal`, past `overdue`.
- Colors: urgent `#FEE2E2` background / `#B91C1C` text; soon `#FEF3C7` / `#92400E`; normal `#F3F4F6` / `#374151`; banner background `#FFF8EB`, border `#F3D9A4`, countdown `#B45309`; page background `#F7F8FA`. All colors are defined in `src/ui/tokens.css`; components never hard-code colors.
- Course palette (assigned in order): `#2563EB #EA580C #059669 #7C3AED #0891B2 #CA8A04 #DB2777 #4F46E5`.
- Fonts: Inter; JetBrains Mono for the countdown.
- All user-facing text lives in `src/ui/i18n.ts` (at the time in two languages).
- Upload nothing; no analytics. No "Purdue" in the name or icon, no university seal.
- Times are stored as ISO 8601 (UTC) and shown in the browser's local time zone.
- After every task `npm test` and `npm run compile` (`tsc --noEmit`) must pass before committing.

## Review Focus

1. **Brightspace's calendar creates a "due" event for each assignment** (titled like "Project 3 - Due"). Students expect each assignment once → Task 5 test `dedupes calendar "- Due" event against dropbox folder`.
2. **"Tomorrow" across days and time zones** is the next local calendar day, not "within 24 hours", including on DST change days (2027-03-14) → Task 4 test `tomorrow is calendar-based across DST`.
3. **"Done" ticks must survive a re-sync:** keep the tick while the platform item ID is unchanged; after a merge, ticking any source counts → Task 5 test `done flag survives resync and merge`.
4. **Gradescope shows several times per assignment** (release, due, late due): use the due date, never the late due date; "No Due Date" becomes `null` → Task 8 test `picks due date not late due date`.
5. **Many Brightspace enrollments, paged, mixed with past courses:** read every page and keep only current courses → Task 7 test `pages through enrollments and drops ended courses`.
