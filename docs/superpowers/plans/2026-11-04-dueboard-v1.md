# DueBoard v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 做出 DueBoard 第一版 Chrome 插件：自动读取普渡 Brightspace 和 Gradescope 的课程、作业、截止日期和资料链接，在新标签页里用课程卡片 / 日历 / 待办三个视图展示。

**Architecture:** WXT（Manifest V3）插件。所有同步都在后台 service worker 里运行：connectors 带着浏览器已有的登录状态读取平台数据，Gradescope 的 HTML 交给 offscreen document 解析，每个平台最近一次成功的结果存成快照（snapshot）放进 `chrome.storage.local`。界面每次读取时，由纯函数 `buildDashboard()` 把快照、手动数据和用户状态合并成要显示的数据。

**Tech Stack:** TypeScript 5.9、WXT 0.21、React 19、Tailwind CSS 4（`@tailwindcss/vite`）、date-fns 4、Vitest + happy-dom + @testing-library/react、`@wxt-dev/auto-icons`。

**Spec:** `docs/superpowers/specs/2026-11-04-dueboard-design.md`（执行前必须完整读一遍；界面以效果图 https://claude.ai/artifact/XWfaHHvt7Ps131t3qctoyZ 里的“定稿：A + 下一个截止横条”为准）

## Global Constraints

- 运行环境 Node 22；包管理用 npm；锁定 `typescript@~5.9.3`（不要用 7.x）。
- 只支持 `https://purdue.brightspace.com` 和 `https://www.gradescope.com`。
- manifest 权限只有：`storage`、`alarms`、`offscreen`；host_permissions 只有上面两个域名的 `/*`；新标签页用 `chrome_url_overrides.newtab`。不申请 `tabs`、`cookies`、`<all_urls>`。
- 只发 GET 请求，统一带 `credentials: 'include'`；Brightspace 并发不超过 4 个。
- 后台同步周期 30 分钟（alarm 名 `dueboard-sync`）；打开面板时，如果距上次同步超过 5 分钟就自动同步。
- 截止状态：≤48 小时为 `urgent`，≤7 天为 `soon`，更远为 `normal`，已过截止时间为 `overdue`。
- 颜色：urgent 用 `#FEE2E2` 底 / `#B91C1C` 字；soon 用 `#FEF3C7` / `#92400E`；normal 用 `#F3F4F6` / `#374151`；横条底色 `#FFF8EB`、边框 `#F3D9A4`、倒计时字色 `#B45309`；页面背景 `#F7F8FA`。所有颜色定义在 `src/ui/tokens.css` 里，组件不直接写颜色值。
- 课程颜色调色板（按顺序分配）：`#2563EB #EA580C #059669 #7C3AED #0891B2 #CA8A04 #DB2777 #4F46E5`。
- 字体：Inter + Noto Sans SC；倒计时用 JetBrains Mono（Google Fonts）。
- 所有显示给用户的文字都放进 `src/ui/i18n.ts`，同时提供 `zh` 和 `en` 两个版本。
- 不上传任何数据、不加任何统计分析代码。名字、图标里不出现 “Purdue” 字样，也不用学校校徽。
- 时间统一按 ISO 8601（UTC）存储，显示时转成浏览器本地时区。
- 每个任务做完都要保证 `npm test` 和 `npm run compile`（即 `tsc --noEmit`）通过，然后再 commit。

## Review Focus

1. **Brightspace 日历会自动给作业生成一条“截止事件”**（标题常常是 “Project 3 - Due”）。用户期望同一项作业只显示一次 → Task 5 加测试 `dedupes calendar "- Due" event against dropbox folder`。
2. **跨日、跨时区的“明天”判断**：“明天”按浏览器本地的日历日计算，不是“24 小时以内”；夏令时切换当天也不能出错（2027-03-14） → Task 4 加测试 `tomorrow is calendar-based across DST`。
3. **重新同步后“已完成”勾选不能丢**：平台作业 ID 不变，就要保留勾选；作业被合并后，勾选任意一个来源都算完成 → Task 5 加测试 `done flag survives resync and merge`。
4. **Gradescope 一个作业有多个时间**（发布时间、截止时间、迟交截止时间）：必须取截止时间，不能取迟交时间；“No Due Date” 要存成 `null` → Task 8 加测试 `picks due date not late due date`。
5. **Brightspace 课程很多、要翻页，还混有往期课程**：要读完所有分页，并且只保留进行中的课程 → Task 7 加测试 `pages through enrollments and drops ended courses`。
