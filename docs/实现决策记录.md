# DueBoard 1.0 实现决策记录

开发过程中，计划没写到、或需要临时判断的地方，都是我先做了决定再继续。下面列出全部决定，每条都附上原因，以及“如果判断错了会怎样”。你觉得哪条不对，告诉我就能改。

## 一、会影响使用体验的决定（建议你看一遍）

| # | 决定 | 原因 | 如果判断错了 |
|---|---|---|---|
| 1 | “本周 N 项”指**从现在起 7 天内**还没完成的作业，不是“周一到周日”；已逾期的不计入 | 和效果图的感觉一致，周末看也有意义 | 周末时数字和“日历上的本周”对不上 |
| 2 | 课程颜色按课程代码固定分配，不随卡片排序变化 | 卡片顺序每天都会变，颜色不能跟着变 | 无 |
| 3 | 同一门课里，两个平台上标题相同、截止时间相差 1 小时以内的作业，合并成一条；点“去提交”优先打开 Gradescope | 设计文档第 4.6 节的规则 | 合并后显示的时间最多差 1 小时 |
| 4 | **同一个平台**上的两项作业永远不合并（例如 “Homework 3” 和 “Homework 3 - Programming”）。唯一的例外：Brightspace 日历自动生成的截止事件，会和它对应的作业合并 | 最终审查发现，之前这种情况会让第二个作业消失 | 如果日历里有一条手动事件，标题恰好和某个作业相同、时间也在 1 小时内，它会被藏到那个作业后面 |
| 5 | Brightspace 作业或测验没有设置 Due Date、只设了 End Date（关闭时间）时，用关闭时间作为截止时间 | 最终审查发现，很多老师只设关闭时间，之前这类作业会显示“无截止日期” | 少数情况下显示的是关闭时间，而不是另外约定的截止时间 |
| 6 | Brightspace 日历事件只保留“像截止日期”的：标题里要有 due、HW、quiz、exam、project、report 等**完整单词**；已经通过作业或测验读到的事件不重复显示 | 否则每周的 Lecture、Lab Section 都会被当成作业 | 标题起得很奇怪的截止事件会被漏掉（可以手动添加） |
| 7 | 标题里有 exam / midterm / final 的日历事件，归类为“考试” | 方便以后单独显示考试 | 无 |
| 8 | 显示范围：截止时间在 7 天前之后的所有作业，加上没有截止时间的作业 | 设计文档第 4.6 节的规则 | 无 |
| 9 | 某门课的某个接口出错时，这门课其他读取成功的数据照常显示，失败的部分沿用上次同步的结果，卡片上标注“部分数据未同步” | 最终审查发现，之前一个接口出错会让整门课的作业消失 | 无 |
| 10 | 只有“账号级别”的请求失败时，才提示“需要重新登录”；单门课返回 403 只标为“部分数据未同步” | 最终审查发现，之前会错误地提示重新登录 | 无 |
| 11 | Brightspace 日历读取失败时不提示任何信息 | 日历只是补充来源，作业和测验已经覆盖了大部分截止日期 | 只出现在日历里的截止日期缺失时，你不会收到提示 |
| 12 | 已在平台上提交的作业，复选框会自动打勾，并且不能取消 | 平台已经确认提交过了 | 无 |
| 13 | 待办清单里，已完成和已提交的作业放进默认折叠的“已完成”区；“本周”分组指明天之后、7 天以内 | 让未完成的作业更显眼 | 无 |
| 14 | 手动添加作业时如果没填链接，默认链接到这门课的 Brightspace 主页；两个表单都只接受 http/https 网址 | 安全，而且点击后总有地方可去 | 无 |
| 15 | 首次使用引导页：只要还没有成功同步过任何平台就显示 | 插件安装时会自动尝试同步一次，所以不能用“从没同步过”来判断 | 无 |
| 16 | 工具栏弹窗：顶部是“下一个截止”，下面列出接下来 5 项未完成的作业（不含已逾期的） | 弹窗空间小，只放最要紧的 | 已逾期的作业要到完整面板里看 |
| 17 | 设置页里，被隐藏的课程也会列出（方便重新显示）；暂时**不能取消**按课程代码自动完成的合并 | 1.0 先保持简单 | 自动合并错了，目前只能把那门课隐藏 |
| 18 | 合并课程后，原来那门课下手动添加的作业、链接、颜色和隐藏设置都会跟过去 | 最终审查发现，之前这些设置会丢失 | 无 |
| 19 | 每门课的卡片上，同一个平台只放一个入口按钮（比如 Pearson 只放一个）；课程网站链接按网址去重 | 有的课程资料里有几十个 Pearson 链接 | 同一平台的第二个不同入口不会显示（在 Brightspace 里仍能找到） |
| 20 | 日历默认显示周视图；月视图每天最多显示 3 项，多出来的显示 “+N” | 周视图信息更清楚 | 无 |
| 21 | 字体打包进插件（Inter、JetBrains Mono），中文使用系统自带字体；**不从 Google 加载字体** | 遵守“不向第三方发送任何请求”的隐私承诺；中文网络字体有好几 MB | 不同电脑上的中文字形略有差别 |
| 22 | 设置页在新标签页中打开 | 设置项比较多，需要空间 | 无 |
| 23 | 日期显示：跨年时加上年份（例如 “2027年1月12日”） | 11 月看到 1 月的日期时，不加年份容易混淆 | 无 |

| # | 决定 | 如果判断错了 |

| 26 | 诊断页检查登录时改用 `whoami` 接口（`/versions/` 不需要登录也能访问，测不出问题） | 无 |

| 28 | Gradescope 的检查页面用 `/account`；Brightspace 日历请求时带上所有当前课程的 ID | 拿到真实数据后，可能要改一个网址 |
| 29 | Brightspace 和 Gradescope 的示例数据目前是按文档手写的，拿到真实数据后替换 | 解析规则需要按真实数据调整 |
| 30 | Gradescope 里没有作业 ID 的行，用标题生成 ID；页面里出现登录表单就视为未登录 | 作业改名后，“已完成”勾选会丢 |

| 33 | 判断“是否需要重新同步”时，看每个平台最后一次**尝试**的时间，而不是最后一次**成功**的时间 | 失败后最多要等 5 分钟才会自动重试（可以手动点刷新） |
| 34 | 同步期间每 20 秒做一次轻量调用，防止浏览器把后台进程提前关掉 | 同步时多一次很轻的调用 |
| 35 | Gradescope 解析器可以同步或异步返回结果（后台通过 offscreen 页面解析） | 无 |
| 36 | 界面多语言用 `useT()` 钩子，支持即时切换语言 | 无 |
| 37 | 组件结构细节：DueBadge 接收当前时间；AppShell 只负责布局；新增 useStore 和几个设置写入函数 | 无 |
| 38 | 作业标题本身可以点击；平台入口放在“快捷入口”分组里；课程详情通过标题按钮打开 | 无 |
| 39 | 视图内部再按截止时间排序一次（保险起见） | 无 |
| 40 | 课程详情弹窗只用 `showModal()` 打开（截图检查时发现，之前背景不会变暗） | 无 |
| 41 | 商店截图严格 1280×800；英文截图使用英文课程名；介绍页有独立的样式文件，支持深色模式 | 无 |
| 42 | 介绍页、隐私政策和商店文案里的 GitHub 地址先用占位符，等你注册账号后再替换（已替换为 Yokiwa）；上传 GitHub 要等你注册账号后再做 | 无 |

另外还多写了一些计划之外的测试（诊断页、后台消息路由、存储层的各个函数），都是为了让对应的代码有测试覆盖。

## 三、暂缓处理的小问题（以后版本再改）

最终审查列出的这些问题，影响都比较小，所以先记录下来：

1. Brightspace 里 “quickLink” 形式的外部工具链接，目前识别不出是哪个平台
2. 在设置页改颜色的同时，在新标签页勾选“已完成”，极小概率会丢掉其中一次修改
3. 浏览器存储读取失败时，页面会空白，而不是显示错误提示
4. 没有结束日期的旧课程，可能会一直显示（等真实数据来确认）
5. 一门课在 Gradescope 上一个作业都没有时，可能会被误标为“部分数据未同步”
6. Brightspace 测验无法判断是否已提交，做完的测验在 7 天内会显示“已逾期”，需要手动勾选
7. 截止时间刚过的那一分钟内，顶部横条可能还显示 00:00:00
8. 无障碍细节：视图切换不支持方向键；日历的键盘导航；月视图的 “+N” 不能点击
9. 后台用来解析 Gradescope 页面的 offscreen 文档，同步结束后不会关闭
